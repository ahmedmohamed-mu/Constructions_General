# CW-150 — دليل الترحيل وUAT والـCutover

## الحالة والحدود

هذه الحزمة تجهز CW-150 للتنفيذ المنضبط، لكنها لا تمثل قبول المرحلة أو تصريح Production. الحالة الحالية: **Prepared / Execution Blocked** لحين استلام ملفات المصدر، تعيين ملاك البيانات والمختبرين، نجاح Dry Runs وGolden UAT وPilot/Parallel Run، ثم محضر Go/No-Go صريح.

لا تنشئ الحزمة فواتير أو قيودًا أو مدفوعات، ولا ترحل أرصدة افتتاحية، ولا تثبت أو ترقي موديولات على Production. كل تحميل تجريبي يبدأ على نسخة Staging حديثة، ومن خلال Odoo ORM أو أدوات الاستيراد المعتمدة، مع External IDs ثابتة وقابلية إعادة التشغيل.

## ترتيب الترحيل الإلزامي

1. الشركات والفروع والعملات واللغات والمستخدمون.
2. الشركاء وتصنيفات المنتجات والمنتجات ووحدات القياس.
3. Cost Codes وWBS وLocations/LBS والمخازن والمواقع والمعدات.
4. العقود والمشروعات والحسابات التحليلية.
5. BOQ وBudget Baselines بعد تثبيت Revision وExternal IDs.
6. الأوامر المفتوحة والعقود الباطنة وأرصدة المخزون المفتوحة.
7. السلف والاحتجازات والضمانات والمستخلصات المفتوحة.
8. الفواتير المفتوحة والمستندات.
9. الأرصدة الافتتاحية في آخر خطوة فقط وبعد موافقة Finance المكتوبة.

يمنع تحميل كائن تابع إذا فشل قبول الكائن الأب. لا تستخدم أسماء السجلات كروابط؛ تستخدم الأكواد وExternal IDs. كل ملف مصدر يحمل رقم إصدار وتاريخ استخراج ومالكًا وقيمة Hash محفوظة في سجل التنفيذ.

## دورة Dry Run

1. تجميد نسخة مصدر محددة وإنتاج Data Profile: عدد الصفوف، المفاتيح الفارغة، التكرارات، العملات، نطاق التواريخ، والإجماليات المالية.
2. اعتماد Mapping لكل عمود وقيم الاختيار والحسابات والضرائب والمستخدمين المسؤولين.
3. Refresh لنسخة Staging، وتوثيق build/commit وإعدادات الشركة قبل التحميل.
4. تحميل الكائنات بالترتيب السابق مع Batch IDs، والاحتفاظ بعدد المقبول والمرفوض ورسالة كل رفض.
5. معالجة الأخطاء في المصدر أو Mapping؛ لا تعدل المستندات المعتمدة يدويًا لإخفاء خطأ ترحيل.
6. إعادة التشغيل على نسخة نظيفة لإثبات Idempotency وعدم إنشاء نسخ مكررة.
7. تشغيل مصالحة الأعداد والقيم والتكاملات ثم Golden UAT والأمان والأداء.
8. توقيع Dry Run فقط عندما تكون الفروقات صفرًا أو لها Waiver موقع ومحدد الأثر.

ينفذ Dry Run مرتين على الأقل: DR-1 لاكتشاف جودة البيانات وDR-2 كـDress Rehearsal بتوقيتات فعلية وخطة تشغيل كاملة.

## ضوابط المصالحة

الـWorkbook المصاحب هو سجل التحكم المركزي. الحد الافتراضي لكل فرق هو صفر. تشمل المصالحات:

- Stock Valuation مقابل Inventory GL.
- AR/AP Aging مقابل دفاتر العملاء والموردين.
- Retention Receivable/Payable مقابل سجلات العقود والمستخلصات.
- Advances مقابل حسابات السلف وخطط الاسترداد.
- Project Actuals مقابل Analytic Ledger.
- Open Commitments مقابل PO/Subcontract remaining commitments.
- Certified IPCs مقابل سجلات المستخلصات والفواتير المرتبطة.
- Billed/Collected مقابل الفواتير والإيصالات المسواة.
- Opening Trial Balance: مجموع Debit يساوي Credit لكل شركة/عملة/دفعة.

أي فرق يعاد إلى سجل المصدر والـBatch والـExternal ID. لا يقبل تعويض فروق بين شركات أو عملات أو مشروعات.

## UAT والأمان والأداء

- ينفذ كل سيناريو Golden بمستخدمين مسمين يمثلون Creator وReviewer وApprover وNext Responsible.
- يسجل لكل خطوة: المستخدم، الوقت، رقم المستند، Screenshot/Export، النتيجة المتوقعة والفعلية، وDefect ID عند الفشل.
- Negative tests إلزامية: الفصل بين إنشاء واعتماد العقود/المشتريات/المستخلصات، منع المستخدم غير المالي من المؤشرات المالية، حدود الشركات، ومنع تعديل المستند المعتمد أو الملغى إلا بمسار Revision/Reversal.
- اختبار الحجم يستخدم بيانات تركيبية مماثلة للحجم المتوقع، ويقيس أزمنة القوائم والبحث والحسابات وتجهيز BOQ والتقارير، مع تسجيل صفوف الاختبار ونسخة البناء. لا تستخدم بيانات شخصية حقيقية لهذا الغرض.
- أي عيب Critical أو High مفتوح يمنع Cutover. عيب Medium يحتاج خطة ومالكًا وتاريخًا وWaiver من مالك العملية.

## Pilot وParallel Run

يختار مشروع واحد ممثل للعملية، دون أرصدة افتتاحية أو نشر مالي حقيقي. ينفذ عليه المسار من Tender إلى Closeout في Staging. بعد نجاحه، تنفذ دورة Parallel واحدة على الأقل تقارن النتائج التشغيلية والمالية بالمصدر دون ازدواج التسجيل الرسمي. يعتمد Steering Committee النتائج قبل Go/No-Go.

## خطة Cutover الخاضعة للموافقة

### قبل النافذة

- نجاح Regression لجميع الموديولات على commit مرشح ثابت.
- إغلاق Mapping وDR-2 وGolden UAT وSecurity UAT وPilot/Parallel.
- اعتماد قوائم المستخدمين والأدوار وبيانات الشركة وETA، وخطة التواصل والدعم.
- نسخ احتياطي كامل قابل للاستعادة واختبار Restore مستقل.
- توقيع Freeze window ومالك كل نشاط وتوقيت البداية والنهاية المتوقع.

### داخل النافذة

1. تأكيد توقف إدخال المصدر وتسجيل آخر أرقام مستندات.
2. أخذ backup نهائي وتسجيل معرفه ووقت الاستعادة المتوقع.
3. نشر الإصدار المعتمد فقط وفق Odoo.sh process.
4. تحميل Delta master data ثم المستندات المفتوحة.
5. تحميل الأرصدة الافتتاحية فقط بتفويض Finance مستقل.
6. Smoke tests، Reconciliation، ETA readiness، وفحص المستخدمين.
7. اجتماع Go/No-Go؛ لا يفتح النظام للمستخدمين قبل التوقيع.

### Hypercare

قناة دعم موحدة، triage مرتان يوميًا، سجل عيوب واحد، SLA حسب الشدة، مراقبة الأداء والتكاملات وETA، ومراجعة يومية للأرصدة والتسويات. تغلق Hypercare بعد استقرار متفق عليه وتوقيع ملاك العمليات.

## Rollback

Triggers: فشل استعادة/سلامة البيانات، فرق مالي غير مفسر، عيب أمني Critical، فشل مسار مالي رئيسي، أو تجاوز النافذة دون اكتمال الحد الأدنى.

عند التفعيل: يوقف الإدخال، يوثق آخر خطوة وBatch، يعزل النسخة الفاشلة، يستعيد backup المعتمد، يعيد توجيه المستخدمين للمصدر، ويراجع سبب الفشل قبل نافذة جديدة. لا يحذف مستندات معتمدة ولا يعالجها مباشرة في PostgreSQL. أي مستند رسمي أنشئ بعد Go-Live يعالج بمسار إلغاء/عكس/إشعار دائن معتمد، لا بالحذف.

## مدخلات لازمة لبدء التنفيذ

- ملفات المصدر الفعلية لكل Object مع Data Dictionary ومالك وتاريخ استخراج.
- الشركات والفروع والعناوين والرقم الضريبي والعملات واللغة والتوقيت.
- Chart of Accounts والجورنالات والضرائب وFiscal Positions وPayment Terms وLock Dates المعتمدة.
- العملاء والموردون والمنتجات ووحدات القياس والمخازن والمواقع.
- المشروعات والعقود وBOQ/WBS/Cost Codes وLocations والأوامر والمستخلصات المفتوحة.
- قائمة المستخدمين المسماة والأدوار وبدائل الغياب.
- إعداد ETA credentials والسياسات في بيئة no-demo المناسبة، دون تضمين أسرار في Git.
- حجم كل مصدر، نافذة التوقف، RPO/RTO، وتاريخ Go-Live المستهدف.

## قرار البوابة الحالي

كل العمل المستقل القابل للتنفيذ مكتمل في هذه الحزمة: قوالب الإدخال، Register، Reconciliation، Golden UAT، Issue Log، Cutover gates وخطة rollback. تبقى CW-150 غير مقبولة حتى تظهر أدلة التنفيذ الفعلية والتوقيعات. لا توجد موافقة ضمنية على Production أو على قيد/فاتورة/رصيد حقيقي.
